# Issue 05：不同 GPX 上傳後仍可能出現不預期來回

## 1) 問題描述
在切換不同 GPX 檔案上傳後，畫面路線仍可能出現「不預期的來回（被額外鏡像一次）」現象。  
特別是 GPX 本身已經包含自然回程或接近閉合時，仍有機會被判定為需再補一段反向路徑，導致路線重複、距離觀感不一致。

## 2) 現況原因
目前判斷重點主要是「起終點距離 + 閉合門檻」的幾何判斷（閉合判斷）。  
這個方式在以下情境不夠穩定：
- GPX 取樣密度不一致（高/低頻混雜）
- 起終點存在 GPS 漂移
- 路線被裁切、分段或含停留抖動
- 路徑方向資訊不足，僅靠空間距離難以區分「自然回程」與「應鏡像補回程」

## 3) 新思路
引入 `trkpt/time` 作為路徑檢核點，讓判斷同時使用：
- **時間序列一致性**（時間是否可解析、是否單調遞增）
- **方向一致性**（時間前進時，路徑索引/前進方向是否合理）

核心想法：不只看「點離得近不近」，還要看「路徑是否依時間合理前進」，以降低誤判來回的機率。

## 4) 建議演算法（含時間存在/缺失時的分層 fallback）
### Step 0：資料前處理
- 解析每個 `trkpt`：`lon/lat/ele/time?`
- 建立 `timeMs`（可解析才給值），並計算：
  - `timeCoverage = 有效 time 點數 / 總點數`
  - `monotonicRatio = time 單調遞增比例`

### Tier A（時間充足，優先）
適用條件：`timeCoverage` 高且 `monotonicRatio` 高（例如 coverage >= 0.7、monotonic >= 0.95）。  
流程：
1. 建立累積里程 `cumDist[i]` 與時間序列 `timeMs[i]`。  
2. 以固定時間窗或距離窗抽樣檢核點。  
3. 檢查「時間前進時，路徑前進方向是否一致」：若長段落出現異常反轉，再判定是否為自然回程而非需鏡像補線。  
4. 綜合閉合條件與時間/方向檢核，輸出 `routeMode`：  
   - `already-round-trip`（直接用原始 GPX）  
   - `needs-mirror-return`（才做反向補點）

### Tier B（時間部分缺失）
適用條件：有部分 `trkpt/time`，但不足以全程信任。  
流程：
1. 用有時間的區段做錨點檢核（局部時間序列 + 方向）。  
2. 無時間區段退回空間連續性判斷（距離趨勢、方位變化）。  
3. 以加權分數整合（時間錨點權重 > 幾何閉合權重）產生 `routeMode`。

### Tier C（無時間，最終 fallback）
適用條件：幾乎沒有可用 `trkpt/time`。  
流程：
1. 保留現行閉合判斷（起終點距離 / 路線長度 / 閉合門檻）。  
2. 增加保守防呆：方向反轉比、重疊比例等幾何訊號，避免單一門檻誤判。  
3. 若信心不足，採「不鏡像優先」或輸出明確診斷訊息供人工確認。

## 5) 修正方向（先計畫，不改碼）
1. 在 GPX 解析階段納入 `trkpt/time`（保留與現有欄位相容）。  
2. 抽出 `decideRouteMode(...)` 決策函式，實作 Tier A/B/C 分層判斷。  
3. `applyLoadedRoute(...)` 僅依 `routeMode` 決定是否鏡像補回程，不再只靠起終點距離。  
4. 增加診斷日誌：輸出命中 Tier、coverage/monotonic、最終 mode 與主要判斷依據。  
5. 先以規格與樣本驗證，確認行為穩定後再進入實作。

## 6) 驗收準則
- 上傳「已含自然回程且時間序列正常」的 GPX，不再被額外鏡像一次。  
- 上傳「需要補回程」的 GPX，仍能正確產生來回路徑。  
- `trkpt/time` 缺失或部分缺失時，能自動進入對應 fallback，且不拋錯。  
- 日誌可清楚看到：使用哪一層 Tier、主要指標數值、最終 `routeMode`。  
- 不影響既有上傳流程、播放可用性與動畫基本行為。
