# Issue 04：上傳 GPX 後標題內容看似未更新

## 1) 問題描述
使用者上傳新的 GPX 後，畫面標題（`#route-title`）在部分檔案情境下仍顯示原本預設文字（例如「玉山主峰單攻」），造成「上傳成功但標題沒變」的觀感，容易被誤判為上傳未生效。

## 2) 重現步驟
1. 開啟頁面，確認初始標題為預設值。  
2. 準備一個可正常解析 `trkpt` 的 GPX，但不含 `<trk><name>`，或 `<name>` 內容為空字串/僅空白。  
3. 點擊「上傳 GPX」並選擇該檔案。  
4. 觀察上傳狀態顯示成功。  
5. 檢查頁面標題：仍是預設標題，視覺上像是沒有更新。

## 3) 目前行為 vs 預期行為
**目前行為**
- 上傳成功後，若 GPX 的 `trk/name` 缺少或為空，標題會回到預設標題。
- 因為預設標題通常與初始畫面一致，使用者會以為新 GPX 沒有被套用。

**預期行為**
- 上傳成功後，標題應反映「目前載入的是新檔案」。
- 當 `trk/name` 缺少或為空時，應使用可辨識的替代標題策略（例如檔名或「未命名路線」），避免看起來像未更新。

## 4) 初步根因
- `parseGpxRoute` 解析 `trk/name` 時，若節點缺少或內容為空，`gpxTrackName` 會變成空字串。  
- `applyLoadedRoute` 目前使用 `gpxTrackName || defaultRouteTitleText` 設定標題。  
- 因此在「GPX 缺少/空的 `trk/name`」情況下，會 fallback 回預設標題，視覺效果就像標題沒有更新（即使路線資料其實已更新）。

## 5) 修正方向（不修改程式碼，只寫計畫）
1. 先定義標題決策優先序（規格層）：  
   - 第一優先：非空白 `trk/name`  
   - 第二優先：上傳檔名（去副檔名）  
   - 第三優先：固定占位字串（例：`未命名 GPX 路線`）
2. 將「預設內建路線標題」與「上傳檔案缺名時的替代標題」分離，避免兩者共用同一 fallback。  
3. 補充 UI/文案規格：上傳成功訊息可同時帶出實際採用的標題來源（trk/name、檔名或占位字串）。  
4. 盤點相依欄位（例如描述欄位 `metadata/time`）是否也需要一致的 fallback 規則，避免標題與描述行為不一致。  
5. 補齊測試案例規格（有名、缺名、空名、僅空白）並納入驗收。

## 6) 驗收準則
- 上傳含有效 `trk/name` 的 GPX：標題顯示該名稱。  
- 上傳缺少 `trk/name` 的 GPX：標題不再顯示「內建預設標題」，而是顯示替代標題策略結果。  
- 上傳 `trk/name` 為空字串或僅空白：行為與「缺少 `trk/name`」一致。  
- 上傳成功訊息與畫面標題一致，使用者可明確辨識目前載入的是新檔。  
- 不影響既有上傳成功/失敗流程與播放可用性判斷。

## 7) 相關程式位置（index.html 行號區段）
- `133-136`：預設標題與預設描述初始化（`defaultRouteTitleText` / `defaultRouteDescriptionText`）。  
- `450-458`：GPX 解析與 `trk/name` 讀取（空值會變成空字串）。  
- `488-516`：套用載入結果到 UI（含 `routeTitleEl.textContent = gpxTrackName || defaultRouteTitleText`）。  
- `519-523`：`loadRouteFromGpx` 呼叫鏈（讀取 → 解析 → 套用）。  
- `837-857`、`920-923`：上傳流程與檔案變更事件進入點。
