# 細節調整計畫（plan-detail）

## 背景與現況
- 目前播放路徑已調整為 **raw-forward**，不再做鏡像補回程；播放會停在原始 GPX 終點。
- A/B 端點目前以原始 GPX 首末點為錨點來源，路線重載後可同步更新；起終點重疊時已有自動錯開邏輯。
- 仍有三個主要缺口：  
  1) RWD 僅基本可用，手機情境下可讀性與操作空間有限。  
  2) A/B 尚未達成「A=綠、B=紅」且與移動點同尺寸的視覺規範。  
  3) 現有旗標偏 2D 疊層，與 3D 地形場景的立體感不一致。

## 問題定義
1. 小螢幕下地圖、控制列與資訊區容易擁擠，影響操作效率與辨識。
2. 起終點雖可辨識，但顏色語意與尺寸一致性不足，視覺優先級不夠穩定。
3. 旗標缺乏立體深度，整體視覺風格與地形呈現不一致。

## 目標
- 提升跨裝置（桌機／平板／手機）可用性與可讀性。
- 讓 A/B 明確符合規範：**A 為綠色、B 為紅色，且尺寸與移動點一致**。
- 強化旗標立體感，同時維持效能與穩定性。
- 確保既有語意不回退：播放終點維持原始 GPX 終點，A/B 持續對應原始首末點。

## 分項方案

### 1) RWD
**方案選項**
- 方案 A（低成本）：僅調整 CSS breakpoints（字級、間距、控制列換行）。
- 方案 B（建議）：在 A 基礎上，加入地圖高度分級、控制列堆疊、觸控區放大、視窗變更後地圖重算策略。
- 方案 C（高成本）：mobile-first 版面重構（資訊與地圖分區/分頁）。

**建議採用**：方案 B。  
**原因**：不需大改資訊架構即可顯著改善手機可用性，風險與工期可控。

### 2) A/B 大小與顏色（A 綠、B 紅）
**方案選項**
- 方案 A（建議）：用 `circle + text` 表現 A/B，半徑直接對齊移動點 size 規則；A 綠、B 紅。
- 方案 B：延續旗標 sprite，重繪顏色與尺寸版本（資產維護成本較高）。
- 方案 C：雙層樣式（外框+內圈）增強可見性（視覺較佳但配置較複雜）。

**建議採用**：方案 A（必要時加上 C 的外框強化）。  
**關鍵約束**：A/B 錨點來源維持原始 endpoints，不因播放路徑更新而改變語意。

### 3) 旗標立體感
**方案選項**
- 方案 A（建議，2.5D）：沿用既有資料層，增加旗桿/旗面的高低層次、陰影與高光表現。
- 方案 B（高擬真）：導入 3D model/custom layer（真實感高，但成本與相容風險高）。
- 方案 C（中成本）：多角度 sprite 切換，模擬立體視角。

**建議採用**：方案 A。  
**原因**：可快速提升立體感且風險較低，適合先行落地。

## 風險與取捨
- RWD 改動過大可能影響桌機排版；需以 breakpoint 分層控制，避免全域覆蓋。
- A/B 尺寸與移動點完全一致時，某些縮放下辨識度可能不足；可用外框/字重補強。
- 旗標立體特效若過重，低階裝置可能掉幀；需保留簡化樣式或降級路徑。
- 必須明確守住語意：播放停止點與 B 端點都對應原始 GPX 終點。

## 驗收標準
1. **語意一致**
   - 播放仍為 raw-forward，且停止在原始 GPX 終點。
   - A/B 仍錨定原始 GPX 首末點；上傳新 GPX 後可正確同步更新。
2. **RWD**
   - 手機（≤768px）可完整操作播放與上傳，按鈕不重疊、文字不截斷。
   - 視窗尺寸變化後地圖不變形，控制可正常互動。
3. **A/B 樣式**
   - A 顯示綠色、B 顯示紅色。
   - A/B 尺寸與移動點一致（同一組 size/radius 規則）。
4. **旗標立體感**
   - 常用縮放與 pitch 下可辨識立體層次，無明顯錯位或閃爍。
5. **穩定性**
   - 不新增 layer/source/image 重複註冊錯誤，不影響既有上傳與播放流程。

## 執行步驟（分階段）
### Phase 0：基線確認
- 確認並固定不可回退條件：playback endpoint 與 raw endpoint anchors。
- 準備手動驗證組合：預設 GPX、上傳 GPX、近閉合路線。

### Phase 1：RWD 強化
- 完成 breakpoint 與控制列堆疊策略。
- 補齊視窗/方向改變時的地圖重算與互動區調整。

### Phase 2：A/B 色彩與尺寸一致化
- 實作 A 綠/B 紅樣式規則。
- 對齊 A/B 與移動點尺寸基準，驗證各縮放層級一致性。

### Phase 3：旗標立體感（2.5D）
- 加入旗桿、旗面陰影與層次效果。
- 建立低效能情境的簡化樣式（必要時降級）。

### Phase 4：整體驗收與回歸
- 依驗收標準逐項檢查並記錄結果。
- 回歸確認不影響上傳、播放控制與既有防呆流程。
